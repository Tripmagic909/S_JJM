# FC版「忍者じゃじゃ丸くん」ROM解析メモ

対象: `忍者じゃじゃ丸くん (J).nes` (32784 bytes, iNES形式, PRG 16KB x1, CHR 8KB x2,
mapper 87 = Jaleco JF-xx系, CHR固定バンク切替のみでPRGバンク切替なし)。
ROM自体はリポジトリに含めない。ツール: `cc65`パッケージの`da65`(6502逆アセンブラ)。

## ベクタ

- NMI(毎フレーム割り込み) = `$8003`
- RESET = `$812F`
- IRQ = `$80AD`

NMI(`$8003`)は `$2003`に0を書いて`$4014`にDMA元ページ(`$02`)を書き込み、
CPU RAM `$0200`-`$02FF`(OAMシャドウバッファ)をまるごとPPUのOAMへ転送する、
一般的なNESの定型処理。実際のスプライト内容は他のルーチンが毎フレーム
`$0200`-`$02FF`を書き換えることで決まる。

## パレットテーブル

PRG-ROM オフセット `0x2b60` (アドレス `$AB60`) に、8パレット x 4バイトの
静的テーブルを発見(全パレットが`$0F`(黒/透明)で始まる形式):

| パレット | バイト列 | 色(近似RGB) |
|---|---|---|
| BG0 | 0F 00 00 28 | 黒, 灰, 灰, オリーブ |
| BG1 | 0F 16 22 30 | 黒, 暗赤, 青紫, 白 |
| BG2 | 0F 20 16 26 | 黒, 白, 暗赤, サーモン |
| BG3 | 0F 28 16 12 | 黒, オリーブ, 暗赤, 青 |
| **SPR0** | **0F 30 16 0F** | **黒, 白, 暗赤(#983422), 黒** |
| SPR1 | 0F 30 0F 1A | 黒, 白, 黒, 緑 |
| SPR2 | 0F 25 37 0F | 黒, ピンク, タン, 黒 |
| SPR3 | 0F 00 00 00 | 黒(未使用) |

**SPR0(黒/白/暗赤/黒)がじゃじゃ丸(頭部)の配色**と特定。ユーザー指定の
「赤白2色、黒は抜き色」と一致する。

## タイトル画面のスプライト配置(OAM静的テーブル)

RESET直後のタイトル/デモループ(`$8165`〜)で、`$8181`のループが
PRG-ROM上の20スプライト分(80バイト、アドレス`$86DD`)を`$0200`へ
まるごとコピーしている。これはOAMの生データ(Y, タイル番号, 属性, X)の
静的テーブルで、タイトル画面のキャラクター全身像を構成している。

- タイル`$00`-`$0F`(16枚、4x4配置、パレットSPR1=白/緑) = 体(緑のカエル状の胴体)
- タイル`$26`-`$29`(4枚、2x2配置、パレットSPR0=白/暗赤) = 頭部、体の上に重ねて配置

これはユーザーが最初に提示した参照画像(オレンジ/赤の頭+緑の胴体)と
完全に一致し、実在するゲーム内アセットであることを確認した。

CHRデータは2バンク(8KBずつ)あり、このタイトルキャラクターは
**CHRバンク1**(オフセット0x2000-0x3FFF)側のタイルを使用している
(バンク0では同じタイル番号が別の絵になり一致しない)。

## 頭部のみの復元

タイトル画面キャラクターのY座標を調べると、Y=91-99(頭、パレットSPR0)と
Y=96-128(胴体、パレットSPR1)が重なりつつ、色の切り替わりで頭部のみを
正確に分離できる(行ごとに使用色を調べて境界を特定)。頭部のみを
32x15pxで復元し、SG-1000のTMS9918向けに赤(#FC5554)+白+透明(黒抜き)へ
変換したものを `assets/jajamaru_v8_16x16.png` として使用する。

## CHRバンク0のタイル配置規則 (ユーザー提供の解読方法)

CHRバンク0(256タイル、16列x16行で並べた場合)は以下の規則で構成されている
ことが判明(ユーザーからの情報提供):

- **タイル0-79 (ブロック1-5、行0-4)**: 敵キャラクター20体。1体=4タイル
  (左端から順に左上/左下/右上/右下、インデックスは4連続)。
  内容: スケルトン(複数フレーム)、白いおばけ(赤い目、複数フレーム)、
  コイル状/ヘビ状の敵、トゲ玉の敵など。
- **タイル80-111 (ブロック6-7、行5-6)**: 1チップ(8x8)のアイテム32種。
  手裏剣(赤十字型)、爆弾、小判、コイン、鳥居/アーチ状の物、花/星、
  果実(赤丸)など。
- **タイル112-159 (ブロック8-10、行7-9)**: **じゃじゃ丸本体**、12ポーズ
  (待機・歩行(2フレーム)・まきびし投げ等のアニメーション)。
- **タイル160以降 (ブロック11+、行10+)**: 追加の敵キャラクター
  (メガネ/マスク状の敵、テーブル状の敵等)や、後半は効果音/エフェクト風の
  細かい破片データが混在。

パレットは基本的に**SPR0(黒/白/暗赤)**で敵・じゃじゃ丸とも表示可能。
一部(骨のシルエットなど)は他パレットの方が適切な可能性がある。

この規則により、M3で行った断片的な抽出よりはるかに効率的にキャラクターを
特定できるようになった。詳細な候補選定は次のG2/G3で行う。

### CHRバンク1について

バンク0とは異なり、バンク1(オフセット0x2000-0x3FFF)は**同じ「20体×4タイル」
規則には従っていない**ことを確認した(`bank1_indexed_atlas.png`で目視確認)。
内訳はおおまかに:

- タイル0-47付近: タイトル画面用の断片データ(既出のタイトルキャラの頭部/胴体
  タイル$00-$0F, $26-$29を含む)
- タイル240-287付近: **UIフォント**(`0123456789ABCDEF`, `GHIJKLMNOPQRSTUV`,
  `WXYZ-=.@` の並び)。得点表示等に使用。
- それ以外: 断片的なパーツ・エフェクト風データが混在し、規則的な4タイル
  グループにはなっていない。個別に用途を特定する必要がある。

## 黒(パレット色)と抜き色(透明)の混同バグとその修正

初期の抽出スクリプトは、NESの2bpp CHRタイルの**ピクセル値0(常にハードウェア
透明)**と、**パレットバイト`$0F`(黒、値1/2/3に割り当てられた場合は普通に
描画される不透明色)**を混同し、両方を透明として扱っていた。
SPR0パレット(`0F 30 16 0F`)は値3が`$0F`(黒)であるため、輪郭線・目・口など
本来不透明であるべき黒が軒並み透明(抜き)になってしまい、骸骨の目や
おばけの輪郭が消えるなど、構成が崩れて見える原因になっていた。

修正: 常に「値0=透明」「値1-3=パレットバイトのRGBで不透明描画(仮に`$0F`
であっても不透明)」という対応に統一。`tools/fc_chr_tool.py`の
`palette_to_colors()`に実装済み。ブロック1-5・6-7・8-10・11以降すべてを
再抽出し、黒い輪郭線・目・口などが正しく表示されることを確認した。

## タイル組み合わせツール (Tile Composer)

一部のキャラクター(特に歩行アニメーションなど)は「左端から4タイル連続で
左上/左下/右上/右下」という規則的な組み合わせにならず、片側のタイルだけを
差し替えて別フレームを作る、といった変則的な構成になっている場合がある。
これを自動検出するのはピクセル比較だけでは信頼性が低いため、ユーザーが
手動でタイルの組み合わせを指定できるインタラクティブツール(Artifact、
`Tile Composer`)を作成した。CHRバンク0/1のタイルアトラスをクリックして
任意の行数x列数のスロットに割り当て、キャラ単位で名前を付けて保存し、
最後にJSON形式でエクスポートできる。ここで指定された組み合わせをG2/G3の
候補提示に反映する。

## 手法まとめ(今後の再利用向け)

1. `da65 --start-addr 0x8000 prg.bin -o out.asm` でPRG-ROMを逆アセンブル
2. パレットテーブルは「0x0Fから始まる4バイト組が8個連続」というバイトパターンで
   静的テーブル領域を検索して特定
3. OAM静的テーブルは、RESET直後や主要ループ内の
   `ldx #$NN / lda TABLE,x / sta $0200,x / dex / bpl` のようなループを探して特定
4. タイル番号→実際の絵は、該当CHRバンクを対応パレットで着色して確認
