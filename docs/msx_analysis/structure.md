# MSX版「忍者じゃじゃ丸くん」ROM解析メモ (M1)

対象: `Ninja Jajamaru Kun (1986) (Jaleco) (J) [!].rom` (32768 bytes)。
ROM自体はリポジトリに含めない。本ドキュメントは `z80dasm` による線形逆アセンブルと、
LDIRVM等のBIOSコール引数の静的抽出に基づく構造解析メモ。

## 1. ROMヘッダ / マッピング

- 先頭2バイト `41 42` = `"AB"` = MSX ROMシグネチャ
- INIT vector = `0x4010` (ヘッダのオフセット2-3、リトルエンディアン)
- STATEMENT/DEVICE/TEXT vector は全て0（未使用）
- サイズが32768 = 0xBFFF-0x4000+1 と一致するため、バンク切り替えなしで
  **0x4000-0xBFFF に単純に直結マッピングされる32KB ROM**（メガロムではない）

## 2. 起動シーケンス (0x4010〜)

```
0x4010  DI
        LD HL,(0xFC4A)     ; システム変数からスタック位置を取得
        LD SP,HL
        CALL 0x0138        ; メインROM内の未特定ルーチン(初期化系、詳細未解析)
        ...ジョイスティックポート/DIPスイッチ読み取りらしき処理...
        LD A,0x0F
        LD (0xF3E9),A      ; FORCLR (前景色) = 15 (白)
        XOR A
        LD (0xF3EAh),A     ; BAKCLR (背景色) = 0
        LD (0xF3EBh),A     ; BDRCLR (枠色)   = 0
        LD A,(0xF3E0)      ; RG1SAV (VDPレジスタ1のBIOSシャドウ)
        OR 0x02            ; bit1 = SI (スプライトサイズ16x16) をON
        LD (0xF3E0),A
        CALL 0x0072        ; INIGRP … SCREEN 2 (Graphics II) 初期化
        CALL 0xB648        ; ゲーム独自の追加初期化
        ; 0xE000-0xEFFFを4096バイト0クリア (ワークRAM初期化)
        LD A,2 : LD (0xE0B8),A
        ; H.TIMIフック(0xFD9F)に "JP 0x4072" を書き込む
        JP 0x40DF
```

### 重要な発見
- **SCREEN 2 (TMS9918 Graphics II) を使用**。BIOSの `INIGRP` (0x0072) 呼び出しで初期化。
- **スプライトは16x16モード**（RG1SAVのbit1を立ててからINIGRPを呼ぶことで設定）。
- **メインの毎フレーム処理はポーリングループではなく、H.TIMI（垂直帰線割り込みフック、
  システム変数0xFD9F）に自前ルーチン(0x4072)を仕込むことで駆動**している。
  BIOSの割り込みハンドラが毎フレームこのフックを呼び出す仕組み。
  → SG-1000移植では、VDPのVBlank割り込み(IM1、0x0038固定ベクタ)で同等の
    「毎フレーム処理」を呼ぶ構成にすれば自然に対応できる。

## 3. VRAM レイアウト (SCREEN 2 / Graphics II)

LDIRVM呼び出し(下記4節)の書き込み先(DE)を集計した結果、以下の非デフォルトな
配置を使用していることを確認:

| 領域 | アドレス | サイズ |
|---|---|---|
| パターンジェネレータテーブル (3バンク) | 0x0000 / 0x0800 / 0x1000 | 各0x800 (2KB) |
| カラーテーブル (3バンク) | 0x2000 / 0x2800 / 0x3000 | 各0x800 (2KB) |
| ネームテーブル | 0x3800 | 0x300 (768バイト, 32x24) ※実際は0x1C0(14行)や0x1E0(15行)単位の部分更新が多い |
| （推定）スプライト属性テーブル/パターンテーブル | 0x3B00付近 | 未確定 |

BIOSデフォルト(ネームテーブル0x1800)ではなく、ネームテーブルをカラーテーブル直後の
0x3800に置く構成。3バンクの色/パターンテーブルをフルに使う設計のため、低位VRAMを
ネームテーブルに割かず上位にまとめたと考えられる。

**SG-1000移植方針**: このアドレス配置自体を踏襲する必要はない(自由に決めてよい)が、
「パターン/カラーとも3バンク(上段/中段/下段で別絵)」という設計思想は踏襲する価値がある。

## 4. グラフィックロード方式 (LDIRVM多用)

`LDIRVM` (BIOS 0x005C, メモリ→VRAM転送) が**72箇所**で呼ばれている。これは
「レベルデータをリアルタイム生成」ではなく、**画面ごとに用意されたパターン/カラー/
ネームテーブルの完成データをVRAMに丸ごと転送する**方式であることを示す。

観測できた技法:
- **バンク間のパターン共有**: 同じ転送元(HL)を3バンク(0x0000/0x0800/0x1000)へ
  繰り返しコピーし、共通タイル(背景/文字など)を3バンク分複製している
  (例: `0x497c/0x4987` は同一ソース0x8d83を使用)。
- **後半キャラクタのみ差し替え**: 各バンクの後半(+0x400)だけ別ソースで上書きし、
  段(上/中/下)ごとに絵が変わるキャラ(自機・敵など)を実現。
- **ネームテーブルは面ごとに丸ごと差し替え**: `0x3800`への書き込みが多数箇所
  (0x5133, 0x5181, 0x520d, 0x5298, 0x543e, 0x5654, 0x5939, 0x5d0e, ...)にあり、
  面が変わるたびにネームテーブルを新しいレイアウトで上書きしていると見られる。
  1回あたり448〜512バイト(14〜16行分、画面下部のステータス表示領域を除いた
  プレイフィールド部分のみ)。

**ポート移植への示唆**: ネームテーブルのバイト列は「どのタイル番号をどこに置くか」
という**面レイアウト情報そのもの**であり、グラフィック(ドット絵)とは独立している。
タイル番号の意味(何番が土/梯子/敵初期配置か等)さえ対応付けられれば、
面レイアウトの「配置そのもの」はSG-1000版でも参考にしやすい。ただし絵は新規に
描き起こす方針のため、タイル番号の再割り当てが必要になる見込み。

参考として、抽出した2種類のタイルセット/画面を再構成した画像を添付する
(静的解析による近似復元のため、多少の欠落・ズレがある点に注意)。

## 5. ゲーム状態管理

- `0xE080`: メインの「ゲームモード」変数（0=タイトル/デモ系、1=ゲーム中、など）
- `0xE081`: サブフラグ（0072呼び出し分岐や、他多数の条件分岐で参照）
- 0x40FCと0x4112付近に**2種類のジャンプテーブル**があり、`0xE080`/`0xE081`の値で
  どちらを使うか分岐した上で、状態値を添字にディスパッチする一般的な
  ステートマシン構造 (`ADD A,A → HL+=BC → JP (HL)`)。
- `0xE100`-`0xEEFF` (約3.75KB) は面開始時にゼロクリアされる大きな配列。
  敵/弾などのオブジェクトスロットテーブルの可能性が高い。
- `0xE0B2/E0B5/E0B8`: ROM上の固定テンプレート(0x1862/0x1876/0x186D、各3バイト)を
  ロードする3つの構造体。自機/敵の初期パラメータ(座標+状態等)と推測。

**SG-1000移植への示唆**: 状態遷移の「設計」自体（タイトル→デモ→ゲーム→ゲームオーバー
のようなモード分岐)はそのまま参考にできる。RAM配置・アドレス自体は当然SG-1000側で
新規に設計し直す。

## 6. 入力処理

`GTSTCK` (BIOS 0x00D5, 8方向スティック読み取り) と `GTTRIG` (0x00D8, トリガー
ボタン読み取り) を使用（各プレイヤー分、複数回呼び出し確認）。読み取った方向を
上下(H)/左右(D,E)の移動量に変換するコードが 0x4094 にある。

**SG-1000移植への示唆**: SG-1000のジョイパッドはポート0xDC(1P)/0xDD(2P)から
1回のINで8方向+2ボタンが読み取れるため、MSXのBIOSコールより単純。方向変換ロジックの
「意味」だけ引き継ぎ、実装はSG-1000のポートリードで作り直す。

## 7. サウンド

`WRTPSG` (BIOS 0x0093) / `RDPSG` (0x0096) 経由でAY-8910 (PSG) を操作。
効果音/音楽の再生は共通のディスパッチャ `0xB5DB` から行われており(21箇所から呼び出し)、
内部でコマンドバイト列テーブル `0xB966` を参照してPSGレジスタ書き込み列を実行する
簡易シーケンサ形式になっている。

**SG-1000移植への示唆**: SG-1000のPSGはSN76489で、AY-8910とはレジスタ構成が
大きく異なる(トーン/ノイズの指定方法、音量ステップ数(16 vs 4bit)等)。
シーケンサの「構造」(コマンド列→レジスタ書き込み)は参考にできるが、
実際のレジスタ値・音色データはM6で全面的に作り直す必要がある。

## 8. BIOSコール使用状況まとめ

| アドレス | 名称 | 呼び出し回数 | 用途 | SG-1000での対応 |
|---|---|---|---|---|
| 0x005C | LDIRVM | 72 | RAM→VRAM転送 | 自前ルーチンで代替(容易) |
| 0x0056 | FILVRM | 16 | VRAM塗りつぶし | 自前ルーチンで代替(容易) |
| 0x004D | WRTVRM | 6 | VRAM1バイト書き込み | 自前ルーチンで代替(容易) |
| 0x0044 | ENASCR | 6 | 画面表示ON | VDPレジスタ1のBLANKビット操作 |
| 0x0041 | DISSCR | 6 | 画面表示OFF | 同上 |
| 0x00D8 | GTTRIG | 5 | トリガー読み取り | ジョイパッドポート読み取りに置換 |
| 0x0096 | RDPSG | 4 | PSGレジスタ読み取り | SN76489は読み取り不可のため設計変更要 |
| 0x0093 | WRTPSG | 4 | PSGレジスタ書き込み | SN76489向けに全面移植(M6) |
| 0x008D | GRPPRT | 4 | グラフィック画面への文字表示 | 自前フォント描画ルーチンで代替 |
| 0x00D5 | GTSTCK | 3 | 8方向スティック読み取り | ジョイパッドポート読み取りに置換 |
| 0x0072 | INIGRP | 2 | SCREEN2初期化 | VDPレジスタ直接設定で代替 |
| 0x0024 | ENASLT | 1 | スロット切り替え | 該当なし(SG-1000にスロット概念なし) |

## 9. 現状グラフィックの参考画像

静的解析で復元した2種のタイルセット/画面（近似復元、一部欠落あり）:
- `msx_tileset_A.png` / `msx_screen_A.png`: 起動直後にロードされる共通タイルセット
  (0x497c-0x4a20周辺のLDIRVM群) + 面レイアウト例
- `msx_tileset_B.png` / `msx_screen_B.png`: 別クラスタ(0xb001-0xb06f周辺)のタイルセット
  + 面レイアウト例（梯子・足場・アイテムらしき絵柄が確認できる）

これらはM3のグラフィック方針決定（FC版寄りの高品質化）における「現状比較用の
たたき台」として使う。リポジトリにはこれらの画像・ROMは含めない。
