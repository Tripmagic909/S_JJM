# TMS9918 "Screen 1.5" ハイブリッドモード

SG-1000移植では、VDPのGraphics II(M3=1)モードを「Screen 1.5」と呼ばれる
ハイブリッド設定で使用する。

## 仕組み

Graphics IIモードでは通常、ネームテーブルの行が画面の上段/中段/下段
(8行ずつ、「third」と呼ぶ)のどれに属するかに応じて、パターン/カラー
テーブルがそれぞれ3つの2KBバンクに分かれる(合計パターン6KB+カラー6KB)。
これにより「段ごとに絵が変わるキャラ」を実現できる代わりに、大量のVRAMと
描き分けの手間を必要とする。

実際のアドレス計算式(vrEmuTms9918などの実機互換エミュレータ実装で検証済み):

```
pageThird   = ((row_in_screen >> 3) & 0x03) & (R4 & 0x03)
pattAddr    = ((R4 & 0x04) << 11) + (pageThird << 11) + charCode*8 + line
colorThird  = (pageThird << 11) & ((R3 & 0x60) << 6)
colorAddr   = ((R3 & 0x80) << 6) + colorThird + charCode*8 + line
```

ポイントは **R4のbit0-1、R3のbit5-6が実際の段番号とのANDマスクとして働く**こと。
これらを`0`にすると、実際の段(0,1,2)に関わらずマスク後の値が常に`0`になり、
3バンクが**同じ1バンクに収束**する。

## Screen 1.5 の設定

- R0 = 0x02 (M3=1、Graphics II選択)
- R4 = 0x00 → パターンテーブルは0x0000の2KB一本のみ(256キャラクタ分、複製不要)
- R3 = 0x80 → カラーテーブルは0x2000の2KB一本のみ、ただし**1キャラクタにつき
  8バイト(1ピクセル行ごとに前景色/背景色ペア)**というGraphics II本来の
  カラーテーブル形式は維持される

## 得られる効果

- 必要VRAM: パターン2KB+カラー2KB (Graphics I相当の footprint)
- 発色: **1キャラクタ内の8ピクセル行それぞれに別の前景色/背景色ペア**を
  設定できる(Graphics Iは8キャラクタごとに1色ペアしか持てない)
- 結果として、Graphics Iよりずっと少ないVRAM負荷でFC版に近い階調表現が可能になる

`tools/headless/harness.c` の `render_screen()` はこの一般化された計算式で
実装済み。`src/test_screen1_5.asm` で実証済み(1キャラクタの8行に虹色の
ストライプを設定し、画面全体に敷き詰めるテスト。スクリーンショット参照)。

## 注意点

- MSX/SG-1000コミュニティでは「undocumented/hybrid mode」として知られており、
  実機のVDPチップ改版や一部エミュレータで挙動が一致しないという報告がある
  (参考: MSX Resource Centerフォーラムでの実機/エミュレータ差異の議論)。
  実機(または高精度エミュレータ)での最終確認は今後のマイルストーンで行うこと。
- スプライトのパターン/カラーには本手法は関係しない(スプライトは常に
  専用のパターンテーブル1本、カラーは1スプライト1色)。
